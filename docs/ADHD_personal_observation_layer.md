# 개인 관찰 계층 설계 초안

상태: 설계만 작성. 개인 데이터는 수집·생성·색인하지 않았다.

## 목적과 경계

`personal_pattern`은 본인이 남기는 시간·상황·행동 기록에서 반복 패턴을 찾기 위한 별도 컬렉션이다. 이 기록은 **ADHD 진단 기준이 아니며**, ADHD 진단 여부나 치료 효과를 자동 판정하지 않는다. `clinical_knowledge`의 출판물 `Evidence`, `Claim`, `GuidelineSection`, `StudyResult`와 같은 색인에 넣지 않는다.

## 최소 스키마

| 타입 | 필수 필드 | 취급 |
|---|---|---|
| PersonalObservation | 가명 ID, 시각, 관찰 내용, 기록자, 동의 범위 | 자기보고 사실 또는 주관적 느낌으로 표시 |
| PersonalContext | 수면·스트레스·장소·업무 등 사용자가 직접 제공한 맥락 | 원인으로 추정하지 않음 |
| PersonalPatternSummary | 집계 기간, 입력 기록 ID, 요약 방법, 불확실성 | 탐색 결과로 표시; 임상 Claim으로 승격 금지 |

민감 정보는 최소한으로 저장하고, 수정·삭제 가능하도록 하며, 이 계층에 대한 접근 권한을 별도로 관리한다. 아직 데이터 모델을 실제 스토리지에 배포하지 않았으므로 보존 기간·동의 UX는 구현 전에 정해야 한다.

## 허용 질의와 차단 규칙

- 허용: “내 기록에서 업무 시작 지연이 많이 적힌 시간대는?”, “수면 기록과 집중 곤란 기록이 함께 나타난 날은?” 같은 **기술적 패턴 질의**.
- 차단: 개인 관찰에서 `SUPPORTS/CONTRADICTS`를 통해 임상 `Claim`을 검증하거나, `DIAGNOSES`·`SATISFIES_DIAGNOSTIC_CRITERIA` 관계를 생성하는 작업.
- 응답에서 개인 기록과 출판물 근거를 분리해 출처를 표시한다. 함께 조회하더라도 개인 패턴과 일반 의학 지식을 하나의 근거처럼 합치지 않는다.
- 평가 자료로 활용할지는 자격을 갖춘 임상의가 임상 면담·병력·기능 영향과 함께 판단한다. 기록 자체가 진단을 확립하지 않는다.

## 출처 추적

개인 기록에는 입력자·입력시각·수정이력을, 문헌 근거에는 원본 위치·해시 또는 외부 ID·수집일·추출 방법·버전을 남긴다. 두 계층 간 자동 승격은 금지한다.
